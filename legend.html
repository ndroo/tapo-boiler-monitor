How to read the screens

What each camera sees, what the icons mean, and how the monitor turns them into readings.

Boiler: HTP UFT-series, P-950EH control

The boiler camera looks at the controller's LCD. Every icon on it is defined by the manufacturer in manual LP-542, Figure 51 (page 48). The monitor sends this annotated drawing to the vision model alongside each capture, so the model identifies segments from the legend rather than guessing.

The pump columns depend on installer settings for pump run-on and boiler-pump mode. "Mode" on the dashboard is derived deterministically: DHW box lit → dhw; else radiator lit → heating; else idle. The flame is tracked separately because a call can be active between burner cycles.

How the boiler reading is produced

  • Every 30 minutes a fresh 1920×1080 still is pulled from the camera through TP-Link's cloud relay (8 frames decoded, sharpest kept).
  • Three images go to Claude: the annotated Figure 51 legend, a small full-frame for context, and a 3× zoom of the LCD panel.
  • The model must answer in a fixed JSON schema (one boolean per icon, plus temperature, clock, error codes, and a confidence level), so a reading can never be malformed.
  • A segment counts as lit only when it is solidly dark. Every segment on an LCD has a faint ghost outline, and ghosts are off.

Zone controller: Taco SR504-EXP

The zone camera watches the relay panel's five LEDs. Top to bottom: POWER, ZONE 1, ZONE 2, ZONE 3, ZONE 4 / PRIORITY. A zone LED is on when that thermostat is calling for heat and the relay has closed.

Light bleeds between neighbouring LEDs, so colour alone is misleading. A lit LED has a blown-out white core; an unlit one is at most a dim coloured dot.

How the zone reading is produced

  • The camera is fixed, so each LED sits at a known pixel position. The monitor measures the fraction of pixels inside a small disc at each LED that are near-white (every channel ≥ 200).
  • Measured over the captures so far: lit LEDs score 0.81–0.96, unlit ones 0.00–0.28 even with heavy bleed. The threshold is 0.50.
  • Only when a LED lands in the ambiguous band (0.35–0.65), or the POWER LED itself looks dark (panel off, or the camera has moved), is Claude asked to confirm from the zoomed image. The dashboard shows which method produced each reading.
  • This makes the zone reading deterministic, repeatable, and nearly free. The per-LED percentages are kept with every reading so the thresholds can be audited.

Thermostats: ecobee (three zones)

Every 15 minutes the monitor signs in to the ecobee account the way the ecobee web app does (no developer API key is needed) and reads each thermostat: indoor temperature, the heat set-point, whether it is calling for heat (any heating equipment listed in the thermostat's equipment status), the fan, the active comfort setting or hold, humidity, and each remote sensor.

  • Tiles show the latest reading per thermostat. An orange edge and "calling for heat" mean that zone's thermostat has closed its heat call; the number after the set-point is how far the room is above (+) or below (−) it.
  • Rooms panel on the timeline: one solid line per thermostat for indoor temperature, dashed for its set-point, in the thermostat's colour.
  • "<name> call" lanes sit under the Taco zone LEDs so the chain can be read top to bottom: thermostat calls → zone relay LED lights → boiler shows a heat call → burner fires → room temperature rises.
  • The account has thermostats at three properties; only the three at 180 Beatrice St are shown here (the others are still logged). ecobee names all three "Home", so they are labelled by model: ecobee4, Smart Thermostat, ecobee3 lite. Which one feeds which Taco zone is not known yet; it will show itself on the timeline when a thermostat's call lines up with a zone LED.
  • The refresh token is stored encrypted in the repo (ecobee_token.enc); the key lives only in a GitHub secret. The password is never stored.

The zone fallback is pinned to Opus. The Model column in the readings table shows which model produced each row and when a confirmation ran.

Timeline conventions

  • Each reading owns the 30 minutes after it, so a bar runs from one capture to the next. Consecutive identical values merge into one bar.
  • A hatched band means the monitor produced no reading for that period (a missed GitHub Actions run; they are scheduled every 30 minutes). It is not a boiler state.
  • A dashed grey lane segment means that field was not captured by the version of the monitor running at the time.
  • White dots on the temperature line mark captures where the burner was firing.
